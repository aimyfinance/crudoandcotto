# Crudo & Cotto — Telegram-бот обліку закупівель, продажів і залишків

Внутрішній облік для ярмаркового причепа: закупівля в Італії (кг, €), роздріб в Австрії, партії з різними цінами, FIFO, звіти у структурі файлу менеджера `облік_2026_БП5.xlsx`.

> Запис продажу в боті — **не фіскальний чек**. Фіскальний облік лишається на касовому апараті; бот імпортує його звіт для звірки.

## Технології та чому

| Що | Чому |
|---|---|
| Python 3.12 + **aiogram 3** | найзріліша бібліотека для Telegram-ботів, FSM «з коробки» для покрокових сценаріїв |
| **SQLite** (WAL) | один файл, нуль адміністрування, вбудований `backup` API; навантаження — десятки операцій на день |
| `decimal.Decimal` для грошей, **цілі грами** для ваги | точність до 1 г і до цента без помилок плаваючої коми |
| `openpyxl` | Excel-експорт у структурі аркушів «Товар» / «Лист3» |
| `threading.RLock` + `BEGIN IMMEDIATE` | одночасні продажі кількох користувачів серіалізуються; перевірка залишку і списання — в одній транзакції |

### Правила, закладені в код

* **Округлення** (`bot/money.py`): проміжні обчислення без округлення; остаточні суми в € — до центів, `ROUND_HALF_UP`; підсумки = сума округлених рядків.
* **Партії**: списання FIFO за датою закупівлі. Собівартість партії = ціна постачальника + додаткові витрати закупівлі, розподілені **пропорційно вазі** (однакова надбавка €/кг на всі позиції закупівлі).
* **Валовий прибуток** = виручка − собівартість проданого (за списаними партіями). Операційні витрати (оренда, пальне, місце на ринку) в боті **не ведуться** — вони лишаються в аркуші «Витрати» у менеджера.
* **Ціни брутто** (з ПДВ). ПДВ окремо не виділяється.
* **Штучні товари** (паста, бурата): у картці задано вагу упаковки; продаж поштучно, списання = штук × вага упаковки.
* **Скасування** не видаляє документ: статус `cancelled`, зворотні рухи в журналі, автор і причина збережені.
* **Ідемпотентність**: повторний `update_id` ігнорується; кнопка підтвердження продажу несе одноразовий ключ — друге натискання не створює другий продаж.
* **Часовий пояс** звітів — Europe/Vienna.

## Ролі

| Роль | Доступ |
|---|---|
| `seller` (продавець) | Продаж, Залишки, Історія (свої продажі, скасування своїх) |
| `manager` | + Закупівля, Товари, Партії, Списання/коригування, Звіти, перегляд користувачів |
| `admin` | + додавання/вимкнення користувачів, резервні копії, відновлення, імпорт звіту каси |

## Структура

```
bot/
  main.py        запуск, middlewares, щоденний бекап, health-порт
  config.py      налаштування зі змінних середовища
  db.py          SQLite, міграції, транзакції, backup/restore
  money.py       Decimal-арифметика, парсинг «12,5», «250 г», «0,25 кг»
  services.py    вся бізнес-логіка (закупівля, FIFO-продаж, списання, звіти, звірка)
  export.py      Excel/CSV у структурі звіту
  cash_import.py імпорт звіту касового апарата
  keyboards.py   меню і клавіатури
  handlers/      сценарії Telegram (sales, purchases, catalog, adjustments, reports, common)
  tools.py       CLI: seed-products, backup, restore, add-admin
migrations/      SQL-міграції (застосовуються автоматично при старті)
tests/           unit- і наскрізні тести (25 шт.)
products.csv     асортимент із файлу менеджера — для масового створення товарів
```

## 1. Створення бота через BotFather

1. У Telegram відкрийте **@BotFather** → `/newbot`.
2. Назва: `Crudo & Cotto Облік`, username: наприклад `crudocotto_bot`.
3. Скопіюйте токен виду `123456789:AAAA...` — це `BOT_TOKEN`.
4. Рекомендовано: `/setjoingroups` → Disable; `/setprivacy` → Enable.
5. Дізнайтесь свій Telegram ID: напишіть боту після запуску — він відповість «Доступ заборонено. Ваш ID: …» (або @userinfobot). Це `ADMIN_IDS`.

## 2. Локальний запуск (ноутбук/Raspberry Pi)

```bash
git clone <репозиторій> crudo_bot && cd crudo_bot
python3 -m venv .venv && source .venv/bin/activate
pip install -r requirements.txt
cp .env.example .env            # впишіть BOT_TOKEN і ADMIN_IDS
python -m bot.tools seed-products products.csv   # (необов'язково) створити товари зі звіту
python -m bot.main
```

Після старту: `/start` у боті → Товари → задайте роздрібні ціни (у `products.csv` вони `0`) → Партії → «Початковий залишок» для того, що вже є на складі, → далі працюйте.

Або через Docker: `docker compose up -d --build` (база в `./data`).

## 3. Розгортання на безкоштовному хостингу

Чесно про «безкоштовно» (стан на 2026 р.):

| Варіант | Постійний диск | Працює 24/7 | Коментар |
|---|---|---|---|
| **Oracle Cloud Always Free** (VM ARM, 4 ядра/24 ГБ) | так | так | найкращий безкоштовний варіант; звичайний Linux-сервер |
| Render / Koyeb (free web service) | **ні** | засинає без трафіку | база зникає при перезапуску → бот сам щодня шле копію в Telegram; після рестарту відновіть її через «Налаштування → Відновити» |
| Railway / Fly.io | так | так | безкоштовного тарифу фактично немає (кілька $/міс) |
| Домашній ПК / Raspberry Pi | так | поки ввімкнено | нуль витрат, повний контроль |

### 3a. Oracle Always Free (рекомендовано)

1. Створіть VM Ubuntu 24 (Always Free shape), підключіться по SSH.
2. `sudo apt update && sudo apt install -y python3-venv git`
3. Виконайте кроки з розділу 2 у `/home/ubuntu/crudo_bot`.
4. Автозапуск: `sudo cp crudo-bot.service /etc/systemd/system/ && sudo systemctl enable --now crudo-bot`
5. Логи: `journalctl -u crudo-bot -f`. Оновлення коду: `git pull && sudo systemctl restart crudo-bot`.

### 3b. Render / Koyeb (без диска)

1. Створіть Web Service з цього репозиторію (Docker). Змінні середовища: `BOT_TOKEN`, `ADMIN_IDS`, `PORT=8080` (бот відкриє health-endpoint `/`).
2. Щоб сервіс не засинав — зовнішній пінгер (UptimeRobot) на `https://<app>/health` кожні 5 хв.
3. Після кожного деплою/перезапуску база порожня → надішліть боту останню резервну копію: **Налаштування → ♻️ Відновити з файлу**.
4. Робіть `/backup` наприкінці кожного ярмаркового дня — файл прийде вам у Telegram.

## 4. Резервне копіювання та відновлення

* **Автоматично**: щодня о `BACKUP_HOUR` (23:00 Відень) бот робить копію (`data/backups/crudo_YYYYMMDD_HHMMSS.db`, зберігається 30 останніх) і надсилає її у `BACKUP_CHAT_ID` (або першому адміну).
* **Вручну**: команда `/backup` або Налаштування → 💾. Або на сервері: `python -m bot.tools backup`.
* **Відновлення**: Налаштування → ♻️ → надіслати `.db`-файл (перед заміною бот робить страхувальну копію, перевіряє цілісність). На сервері: `python -m bot.tools restore crudo_20260915_230000.db`.
* Excel/CSV-експорти — у Звітах, вони ж є «людською» резервною копією даних.

## 5. Синхронізація з файлом менеджера

Звіти → період → **📊 Excel** дає файл з аркушами:

* **Товар** — рядок на кожну партію: залишок на початок, закупівля (кг, ціна, сума), продаж (кг, середня ціна, сума), прибуток, втрати, залишок на кінець — та сама логіка, що в аркуші «Товар» у `облік_2026_БП5.xlsx`;
* **Зведення** — як «Лист3» (надходження/витрати/залишок по товарах + виручка, списання, валовий прибуток);
* **Оплати** — готівка/картка по днях (бот і каса) — для рядків «оплата на картку» / «готівка з каси» аркуша «Витрати»;
* **Продажі за товарами** (маржа), **Залишки** (по партіях), **Операції** (повний журнал).

Менеджер підкладає аркуші «Товар»/«Зведення» замість ручних, а аркуш «Витрати» веде далі як зараз.

## 6. Імпорт даних файлами (Налаштування, лише адмін)

| Кнопка | Файл | Що робить |
|---|---|---|
| Імпорт товарів | `name; category; sale_mode; piece_grams; retail_price; sku` | створює товари, дублікати за назвою пропускає |
| Імпорт початкових залишків | `name; kg; price_per_kg; expiry` | створює партії початкового залишку (кожне надсилання додає!) |
| Імпорт історії руху товарів | аркуш «Рух товарів»: період × товар — закупівля/продаж/списання/залишок на кінець | створює документи за періодами, вирівнює залишки до звіту; повторний імпорт нічого не дублює |
| Імпорт витрат | аркуш «Витрати»: `date; type; category; amount; comment` | типи: Операційні / Оплата товару / Податки / Інвестиції |

Команда `/reset_db` (адмін) очищає всі облікові дані (з резервною копією) — для чистого старту перед імпортом історії.

Витрати можна вносити і вручну: Звіти → ➕ Додати витрату. У звітах: операційний результат = валовий прибуток − списання − операційні витрати − податки (не чистий прибуток: без амортизації та виплат власнику).

## 7. Каса Octobox

Два експорти з бек-офісу Octobox:
* **Список чеків** (Number, Datum, Zahlungsmethode, Betrag) — Налаштування → 🧾 Імпорт звіту каси → звірка виручки по днях (бот ↔ каса).
* **Експорт по позиціях** (Produkt, Betrag, Gewicht (kg) — насправді грами; штучні товари — рядок на штуку без ваги) — Налаштування → 🧾 Імпорт чеків Octobox: бот створює продажі по чеках (готівка/картка, час чека), списує залишки FIFO, обробляє сторно (шукає чек того ж дня з тією ж сумою і скасовує його). Назви каси зіставляються з товарами бота автоматично; сумнівні позначаються 🔸 і їх можна перепризначити кнопкою — прив'язка зберігається (Налаштування → 🔗 Прив'язки назв каси). Повторний імпорт того ж файлу нічого не дублює (ключ — номер чека). Якщо продано більше, ніж є в залишку бота, нестача дооприбутковується автоматично й позначається у звіті імпорту — внесіть закупівлі до імпорту, щоб цього не було.

Рекомендований ритм: після кожного ярмаркового дня (або тижня) вивантажити експорт по позиціях → надіслати боту. Продавцю тоді не треба нічого вводити в Telegram; каса в Mini App лишається для випадків без Octobox.

## 7a. Імпорт звіту каси (загальний формат)

Налаштування → 🧾 Імпорт звіту каси → надіслати CSV/XLSX. Імпортер шукає колонки «Дата»+«Готівка»+«Картка» або «Дата»+«Сума»+«Оплата» (укр/нім/англ синоніми в `cash_import.py`). Потім Звіти → «Звірка з касою» показує різниці по днях. **Формат конкретної моделі каси не бачив — надішліть приклад вивантаження, і я додам точний парсер.**

## 7b. Закупівля з інвойсу (PDF/фото)

Закупівля → «📄 Закупівля з інвойсу» → надіслати PDF або фото. Бот розпізнає документ через Claude API (змінна `ANTHROPIC_API_KEY`, модель `INVOICE_MODEL`, за замовчуванням claude-sonnet-4-6), показує позиції з прив'язкою до товарів, звіряє суму рядків із підсумками документа, виділяє транспорт окремо (розподіляється на партії за вагою). Кожну позицію можна поправити (товар / вага / ціна / пропустити / створити товар). «✅ Оприбуткувати» створює закупівлю і партії; прив'язки «постачальник + артикул → товар» зберігаються, тож наступний інвойс того ж постачальника зіставляється без правок.

## 8. Mini App «Каса» (Telegram Web App)

Повноекранний застосунок усередині Telegram: Каса (плитки товарів, табло ваг, кошик, готівка/картка), Залишки (з партіями), Сьогодні (виручка, валовий прибуток, готівка/картка, топ товарів, продажі з можливістю скасувати). Працює на тій самій базі та ролях; підпис `initData` перевіряється на сервері.

Увімкнути:
1. Railway → сервіс → **Settings → Networking → Generate Domain** (порт 8080). Отримаєте адресу виду `https://crudoandcotto-production.up.railway.app`.
2. Variables → додати `WEBAPP_URL=https://<ця адреса>` → Deploy.
3. У боті з'явиться кнопка **🧾 Відкрити касу** і кнопка «Каса» біля поля вводу.

Файли: `bot/webapp.py` (API), `bot/static/index.html` (інтерфейс). Локально: задайте `PORT=8080`, відкрийте `http://localhost:8080/app` — без Telegram сторінка покаже «Доступ заборонено» (це очікувано, підпис є лише всередині Telegram).

## Що перевірено, а що потребує реального середовища

**Перевірено автоматичними тестами (19 тестів, усі проходять):**
* парсинг ваги/чисел з комою і крапкою, правило округлення (250 г × 28 = 7,00; 1 г × 5 = 0,01);
* закупівля з розподілом транспортних витрат, часткові продажі, різні ціни партій (FIFO 1000 г по 20 + 500 г по 30 → собівартість 35,00);
* заборона продажу понад залишок; 20 одночасних продажів по 150 г з 1000 г → рівно 6 проходять, залишок 100 г;
* списання з причиною, інвентаризація, скасування продажу/списання/закупівлі з відновленням партій; повторне скасування відхиляється;
* дублювання: однаковий `client_key` → другий продаж не створюється; повторний `update_id` ігнорується; подвійне натискання «підтвердити» не дублює;
* штучні товари (2 × 300 г → 28,00 €, списано 600 г);
* аркуш «Товар» дає ті самі цифри, що у файлі менеджера для Prosciutto di Parma (1995,11 / 1127,74 / 342,70 / 727,12; прибуток 202,45);
* Telegram-сценарії через Dispatcher із підробленою сесією: авторизація, ролі, закупівля → продаж → «Назад» → «Скасувати», звіт і Excel-експорт;
* backup/restore.

**Потребує реального токена / сервера (не перевірено тут):**
* фактичне з'єднання з Telegram, відображення клавіатур на телефоні, завантаження документів (`bot.download`);
* щоденне надсилання копії за розкладом (логіка написана, чекає живого бота);
* поведінка на конкретному хостингу (порт, засинання);
* парсинг реального файлу касового апарата.
